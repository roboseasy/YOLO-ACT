## 1. 목표

LeKiwi가 갈색 3D 프린터 상자 1개까지 베이스로 접근해 팔로 집고 정해진 위치에 놓는 작업을 ACT로 학습합니다.
이때 YOLO 바운딩 박스(bbox)를 입력에 더하면 성공률이 오르는지 실물 로봇에서 확인합니다.

- **주 질문:** 영상 + bbox + 관절(실험 3)이 영상 + 관절(실험 1)보다 성공률이 높은가?
- **부 질문:** 영상 없이 bbox + 관절(실험 2)만으로 어디까지 되고, 어느 단계에서 실패하는가?

실험 2는 해볼 만한 시도입니다. 2026-09-04에 규칙 기반 `lekiwi-yolo/yolo_and_pick`이 학습 없이 YOLO 박스와 팔 자세로
접근, 손목 서보, 집기를 실물에서 끝까지 수행했습니다. 다만 집기 성공 판별에는 그리퍼 색 정보를 함께 썼습니다.

## 2. 세 실험

| 실험 | 입력 | 출력 | 데이터셋 | 모델 |
| --- | --- | --- | --- | --- |
| 1 | 영상 2개 + 관절 | 9차원 행동 | `lekiwi_brownbox` | 기본 ACT (파라미터 52M) |
| 2 | bbox + 관절 | 9차원 행동 | `lekiwi_brownbox_bbox_only` | bbox 입력 ACT, 영상 백본 없음 (40M) |
| 3 | 영상 2개 + bbox + 관절 | 9차원 행동 | `lekiwi_brownbox_bbox` | bbox 입력 ACT (52M) |

세 실험의 차이는 입력뿐입니다. 같은 시연으로, 같은 설정으로 학습하고, 같은 조건에서 평가합니다.

## 3. 범위

**이번에 하지 않는 것**

- ACT 구조 변경. 결과를 본 뒤 필요할 때만 합니다(6.3절).
- 라즈베리파이나 Hailo에서의 온디바이스 추론. 모든 추론은 PC에서 합니다.
- 여러 상자 중 지정한 하나 집기, 방 기준 위치로 돌아가기, 실패 후 재시도.
- 다른 정책(SmolVLA 등), 영상 증강, Hub 업로드.

**결과가 좋아 보여도 실험을 무효로 보는 경우**

- 실험마다 시연이나 평가 조건이 달라진 경우.
- 학습 때와 실행 때 bbox 계산이 달라진 경우. 미래 프레임으로 빈 구간을 메운 경우도 포함합니다.
- bbox가 모델에 실제로 들어가지 않은 채 학습이 끝난 경우. 오류 없이 일어날 수 있습니다(6.2절).

## 4. 작업 정의

| 항목 | 내용 |
| --- | --- |
| 로봇 | `lekiwi06` 한 대. 시연과 평가에서 같은 캘리브레이션과 카메라 각도를 유지합니다 |
| 타겟 | 갈색 3D 프린터 상자 1개. 장면에 다른 상자류를 두지 않습니다 |
| 시작 상태 | 바닥에 표시한 고정 위치와 방향, 고정 팔 자세 |
| 상자 배치 | 시작 위치의 정면 카메라에 상자 전체가 보이는 범위. 초기안은 거리 0.4~1.0 m, 좌우 ±30°이고 M0에서 실측해 확정합니다 |
| 상자 방향 | 상자 면이 로봇 시작 위치를 향하도록(±15°) 둡니다. 무작위 방향은 부 조건으로만 평가합니다 |
| 동작 순서 | 회전으로 정렬, 전진, 정지, 팔로 집기, 놓기 |
| 시연 규칙 | 베이스와 팔을 동시에 움직이지 않습니다. 평행이동(`a`/`d`)을 쓰지 않습니다. 바퀴 속도 단계를 바꾸지 않습니다 |
| 놓는 위치 | **로봇 기준 고정 위치.** 로봇 몸체의 트레이 또는 팔이 닿는 로봇 옆 지점이며, 베이스가 멈춘 상태에서 놓습니다 |
| 성공 | 사람 개입 없이 제한 시간 안에 상자가 놓는 위치 안에 있고 그리퍼가 열려 있음 |

**놓는 위치를 로봇 기준으로 잡은 이유.** 베이스가 움직이면 로봇이 방 안 어디에 있는지가 bbox와 관절값에 나타나지 않습니다.
방 기준 위치에 놓으라고 하면 실험 2는 놓을 곳을 알 방법이 없어 공정한 비교가 되지 않습니다.
로봇 기준이면 세 실험 모두 관절값만으로 그 위치까지 갈 수 있습니다.

**시연 규칙을 둔 이유.** 같은 상황에서 시연 방식이 갈리면 ACT가 평균적인 애매한 행동을 배웁니다.
회전 우선과 "팔이 움직일 때 바퀴 정지"는 규칙 기반 구현에서 실물로 검증한 순서이기도 합니다.

## 5. 데이터셋

### 5.1 구조

LeRobot Dataset v3.0입니다. 기존 LeKiwi 형식에 열 하나만 더합니다.

| 키 | 형식 | 내용 |
| --- | --- | --- |
| `action` | float32 [9] | 팔 6관절 목표(도) + 바퀴 목표 속도 3개 |
| `observation.state` | float32 [9] | 같은 9개의 측정값 |
| `observation.images.front` | video 480×640×3, 30 fps | 정면 카메라 |
| `observation.images.wrist` | video 480×640×3, 30 fps | 손목 카메라 |
| `observation.environment_state` | float32 [14] | **추가:** bbox |

### 5.2 bbox 14차원

카메라마다 7개이며 front, wrist 순서로 이어 붙입니다.

| 위치 | 이름 | 값 |
| --- | --- | --- |
| 0~3 | `{cam}_x1`, `{cam}_y1`, `{cam}_x2`, `{cam}_y2` | 좌상단과 우하단 좌표. 이미지 폭과 높이로 나눈 0~1 값 |
| 4~5 | `{cam}_cx`, `{cam}_cy` | `(x1+x2)/2`, `(y1+y2)/2` |
| 6 | `{cam}_is_detected` | 이 프레임에서 검출하면 1, 아니면 0 |

요청하신 6개 값에 `is_detected`를 더했습니다. 없으면 "상자가 안 보임"과 "상자가 좌표 0 근처에 있음"을 구별할 수 없기 때문입니다.
`cx`, `cy`는 나머지 좌표로 계산되는 값이지만 요청대로 그대로 넣습니다.

**계산 규칙**

- 검출이 없으면 좌표는 이번 에피소드의 마지막 검출값을 유지하고 `is_detected`만 0으로 둡니다. 첫 검출 전에는 전부 0입니다.
- 과거 프레임만 씁니다. 실행 때는 미래를 볼 수 없으므로 학습 데이터에서도 보간하지 않습니다.
- 박스가 여러 개면 confidence가 가장 높은 1개를 씁니다. 장면에 상자가 1개라는 전제입니다.
- confidence 임계값은 M2에서 정해 고정합니다. 초기값은 0.3입니다. 화면 모서리에 잘린 상자의 confidence가 0.51~0.59로 측정돼, 0.5로 두면 검출이 깜빡입니다.
- 이 계산은 `BBoxExtractor` 한 곳에만 둡니다. 라벨링과 실행이 같은 코드를 씁니다.
- `is_detected`의 정규화 통계는 평균 0.5, 표준편차 0.5로 고정합니다. 실제 통계를 쓰면 검출률 99.5%일 때 미검출 한 프레임이 -14가 되고, 100%이면 분산이 0이 되기 때문입니다. 고정하면 0과 1이 항상 -1과 +1입니다.

### 5.3 라벨링은 녹화 후 오프라인으로

녹화 중에 YOLO를 돌리지 않고, 저장된 영상으로 bbox를 만듭니다.

- 녹화 루프에 부하를 주지 않아 기존 Physical Labs 수집 기능을 그대로 쓸 수 있습니다.
- YOLO가 좋아지면 시연을 다시 하지 않고 라벨만 다시 만듭니다.
- LeRobot의 `add_features`와 `recompute_stats`로 구현할 수 있습니다. 시험 데이터셋으로 확인했습니다.

대신 라벨은 AV1 영상에서, 실행은 JPEG 스트림에서 계산하므로 차이가 생길 수 있습니다. M2에서 측정합니다.

### 5.4 한 번의 녹화에서 세 데이터셋

```text
lekiwi_brownbox              녹화 원본 (영상 + 관절)                실험 1
  │ label_dataset.py: YOLO 라벨링, 열 추가, 통계 재계산
  ▼
lekiwi_brownbox_bbox         영상 + bbox + 관절                     실험 3
  │ lerobot-edit-dataset remove_feature: 영상 키 2개 제거
  ▼
lekiwi_brownbox_bbox_only    bbox + 관절                            실험 2
```

에피소드 번호와 순서가 같으므로 학습과 검증 분할도 세 실험에서 같습니다.

## 6. 모델

### 6.1 입력 레이어: ACT 코드를 고치지 않습니다

LeRobot 0.6.0의 ACT는 `observation.environment_state`가 있으면 `Linear(14→512)` 입력 레이어를 자동으로 만들어
트랜스포머 인코더의 토큰 하나로 넣습니다. 영상 입력이 없으면 ResNet 백본도 만들지 않습니다.
요청하신 입력 레이어 커스터마이징을 코드 수정 없이 얻는 셈이고, LeRobot을 포크할 필요가 없으며 저장과 불러오기도 그대로 동작합니다.

시험 데이터셋으로 세 구성을 실제로 학습해 확인했습니다. 시험 조건은 배치 8, 100 스텝, 무작위 bbox이고 RTX 5070 Ti Laptop을 사용했습니다.

| | 실험 1 | 실험 2 | 실험 3 |
| --- | --- | --- | --- |
| bbox 입력 레이어 | 없음 | `Linear(14→512)` | `Linear(14→512)` |
| ResNet 백본 | 있음 | 없음 | 있음 |
| 파라미터 | 51.6M | 40.2M | 51.6M |
| 학습 속도 | 4.8 step/s | 약 40 step/s | 4.7 step/s |
| 정책 호출 1회 (입력 생성값) | 10.7 ms | 2.0 ms | 10.8 ms |

### 6.2 오류 없이 잘못되는 지점

| 지점 | 무슨 일이 생기나 | 막는 방법 |
| --- | --- | --- |
| 키 이름 | `observation.bbox`처럼 이름이 다르면 ACT가 조용히 무시합니다. 영상이 있으면 오류도 나지 않습니다 | 키를 `observation.environment_state`로 고정하고, 체크포인트에 `encoder_env_state_input_proj`가 있는지 검사합니다 |
| 정규화 설정 | ACT 기본 설정에 `ENV`가 없어 bbox가 정규화되지 않습니다 | `--policy.normalization_mapping`에 `ENV: MEAN_STD`를 넣습니다. 전달되는 것을 확인했습니다 |
| 통계 누락 | `add_features`는 새 열의 통계를 만들지 않습니다. 통계가 없어도 오류 없이 정규화를 건너뜁니다 | 곧바로 `recompute_stats`를 실행합니다. 통계가 생기는 것을 확인했습니다 |
| 분산 0인 차원 | 학습 데이터에서 값이 변하지 않은 차원은 실행 때 조금만 달라져도 약 1억 배로 커져 로봇이 비정상 동작할 수 있습니다 | 라벨링 때 좌표 차원의 표준편차를 검사하고 `is_detected` 통계를 고정합니다. 실행 중 정규화 값의 절댓값이 50을 넘으면 멈춥니다. 기존 데이터의 바퀴 속도는 학습 데이터 안에서도 10.8까지 나와, 기준을 10으로 두면 정상 동작에서도 멈춥니다 |
| 배열 형식 | `add_features`에 2차원 배열을 넘기면 실패합니다 | 프레임별 함수로 넘깁니다. 동작을 확인했습니다 |

### 6.3 구조를 바꾸는 조건

실험 3의 인코더 입력은 토큰 603개이고 그중 bbox는 1개입니다(잠재 1, 관절 1, bbox 1, 영상 600).
실험 3이 실험 1과 차이가 없으면 bbox 토큰이 묻혔을 수 있습니다. 그때 카메라별 토큰 분리를 2차 실험으로 검토합니다.
1차 결과 없이 먼저 구조를 바꾸면 차이의 원인을 구별할 수 없어 뒤로 미룹니다.

## 7. 실행 구조

매 제어 주기는 다음 순서로 돕니다. 실행 전체는 PC에서 합니다.

```text
관측 수신 → BBoxExtractor.update(front, wrist) → 관측에 14개 값 추가 → ACT → 9차원 행동 송신
```

기존 실행 경로는 이번 조건에 그대로 쓸 수 없습니다.

| 경로 | 문제 |
| --- | --- |
| `lerobot-rollout` | 바퀴 값(`.vel`)을 버립니다 |
| Physical Labs 추론 탭 | 바퀴를 0으로 강제합니다 |
| `lekiwi-evaluate.py` | 9차원은 지원하지만 기본 `LeKiwiClient`를 써서 ROS 호스트에서 영상의 빨강과 파랑이 뒤바뀝니다 |

그래서 성공/실패 판정과 리포트 기능이 있는 `lekiwi-evaluate.py`를 바탕으로 삼고, 클라이언트를 Physical Labs의 ROS용 클래스로 바꾼 뒤 bbox를 주입합니다.

**제어 주기는 현재 환경에서 감당됩니다.** 로봇의 실제 스트림으로 측정했습니다. 명령은 보내지 않았고 로봇은 멈춰 있었으며 Wi-Fi 신호는 -42 dBm이었습니다.

| 항목 | 측정값 |
| --- | --- |
| 스트림 수신 | 30.1 Hz, 메시지당 54 KB, 간격 p95 41 ms |
| YOLO 2회 + ACT(실험 3) 포함 루프 | 28.8 Hz |
| 1주기 처리 시간 | p50 16.5 ms, p95 25.3 ms, 최대 40.8 ms |
| YOLO 2회 | p50 11.3 ms, p95 15.5 ms |
| 정책 호출 | p50 15.5 ms, p95 22.5 ms (11회) |

**행동 실행 길이는 줄입니다.** ACT 기본값은 100스텝(3.3초)을 열린 루프로 실행합니다. 베이스 상한을 0.23 m/s로 보면 그동안 약 77 cm를 새 관측 없이 달리는 셈입니다.
세 실험 모두 실행 때 `n_action_steps=30`(1초)을 쓰고, 파일럿에서 필요하면 temporal ensembling과 비교한 뒤 고정합니다.

## 8. 판단 기준

- **주 지표:** 기본 조건에서 모델별 30회 시도의 성공률. 실험 3과 실험 1을 비교합니다.
- **보조 지표:** 실패 단계(접근, 집기, 놓기, 안전 정지), 수행 시간, 카메라별 검출률, 제어 주기.

| 결과 | 판단 |
| --- | --- |
| 실험 3이 더 높고 Fisher 정확 검정 p < 0.05 | 향상으로 봅니다. 결론을 내기 전에 실험 1과 3을 다른 seed로 한 번 더 학습해, 위치 10개씩 평가로 같은 방향인지 확인합니다 |
| 차이가 20%p 이상이지만 p ≥ 0.05 | 판단 보류. 실험 1과 3을 seed 하나씩 더 학습해 30회씩 추가하고 한 번만 다시 판정합니다 |
| 차이가 20%p 미만, 또는 실험 3이 더 낮음 | 이 조건에서 뚜렷한 향상을 보이지 못했다고 판단합니다 |

모델별 30회로는 약 27%p 이상의 차이부터 구별됩니다. 예를 들어 60% 대 87%는 p = 0.039이고, 60% 대 80%는 p = 0.158입니다.
30회씩 더해 60회가 되면 60% 대 80%도 p = 0.028로 구별됩니다.
이 p값은 평가한 두 체크포인트의 차이만 말해 줍니다. 학습을 다시 했을 때의 변동은 반영하지 않으므로 다른 seed로 방향을 확인합니다.

**기준선 점검.** 본 평가의 첫 반복(모델당 10회)을 마치면 비교가 의미 있는 구간인지 봅니다.

| 첫 반복 결과 | 조치 |
| --- | --- |
| 실험 1이 9회 이상 성공 | 포화입니다. 100개 결과는 기록해 두고, 시연 50개로 실험 1과 3을 다시 학습해 같은 절차로 비교합니다 |
| 실험 1과 3이 모두 2회 이하 성공 | 바닥입니다. 시연을 최대 150개까지 늘려 다시 학습합니다. 그래도 같으면 멈추고 사용자와 논의합니다 |
| 그 외 | 계속합니다. 실험 1만 낮은 것은 문제가 아닙니다 |

상자 배치 범위를 줄이면 bbox가 더할 몫도 줄어, 주 질문이 더 쉬운 과제에 대한 답으로 바뀝니다. 그래서 사용자 결정 없이 줄이지 않습니다.

## 9. 위험 요소

| 위험 | 근거 | 대응 |
| --- | --- | --- |
| 비슷한 물체 오검출 | 상자가 없는 기존 장면에서 `box-2`가 골판지 상자와 빨간 주사위를 box로 잡았습니다. 정면 카메라 프레임의 85%에서 confidence 0.5 이상 박스가 나왔습니다 | 작업 공간에서 상자류를 치우고, M2에서 빈 장면 오검출을 측정합니다. 많으면 음성 데이터를 추가해 재학습합니다 |
| 집는 순간 검출 끊김 | 타겟 상자로는 아직 측정 전입니다. 다른 물체(빨간 주사위)와 다른 모델에서는 그리퍼에 물린 뒤 손목 카메라 검출이 끊겼습니다 | `is_detected`와 값 유지로 처리하고, M2에서 구간별로 측정합니다 |
| 이동 중 번짐, 먼 거리 | 베이스 이동 중과 1 m 부근의 검출률은 미측정입니다 | M2 게이트에서 측정합니다 |
| 상자 방향 정보 없음 | 축 정렬 bbox는 회전 방향을 나타내지 못합니다. 실험 2의 구조적 한계입니다 | 기본 조건은 방향을 ±15°로 제한하고, 무작위 방향은 부 조건으로 평가합니다 |
| 영상 색 뒤바뀜 | 기본 `LeKiwiClient`와 ROS 호스트의 조합입니다. 실험 1과 3에 치명적입니다 | ROS용 클라이언트만 사용하고, YOLO 입력의 색 변환도 `BBoxExtractor` 한 곳에서만 합니다 |
| 베이스 포함 녹화 미검증 | 로컬 데이터셋 6개 모두 바퀴 명령이 0입니다 | M0에서 시험 녹화로 먼저 확인합니다 |
| 키보드 조작의 계단형 속도 | 바퀴 명령이 일정 속도로 켜졌다 꺼집니다 | 시연 규칙으로 일관성을 높이고, 파일럿에서 접근 동작을 확인합니다 |
| 자율 주행 중 충돌 | 정책이 바퀴를 직접 움직입니다 | 처음에는 `base_speed_scale=0.3`으로 시작하고, 사람이 정지 키를 잡으며, 주변을 비웁니다 |
| 조건 변화 | 배터리 저하로 모터 힘이 달라지고, 조명도 시간에 따라 바뀝니다 | 모델 순서를 순환시켜 평가하고 반복마다 충전 상태를 맞춥니다 |

## 10. 검증 상태

**확인한 것** (코드 수정 없이 임시 폴더에서 실행, 로봇에 명령은 보내지 않음)

- LeRobot 0.6.0 그대로 세 구성의 학습, 체크포인트 저장, 불러오기, 검증 손실 계산이 됩니다. 쓴 데이터셋은 기존 3개 에피소드와 무작위 bbox입니다.
- `box-2`로 타겟 상자가 찍힌 11월 7일 영상을 돌리면 프레임의 98~100%에서 검출되고 confidence 중앙값은 0.97~0.98입니다. 이 영상은 학습에 쓰였을 가능성이 높아 낙관적인 수치입니다.
- `box-2`의 YOLO 검증 세트 성능은 mAP50 0.994, mAP50-95 0.957입니다.
- 기존 녹화 데이터의 관측 주기는 약 29 Hz입니다(팔 이동 중 동일 상태 비율 2~3%).
- 로봇 카메라 2대와 상태 토픽은 약 30 Hz입니다.
- `is_detected` 고정 통계는 특징 제거, 학습, 체크포인트를 거쳐 그대로 전달되어 0과 1이 -1과 +1이 됩니다.

**아직 모르는 것**

- 실제 작업 중 타겟 상자의 구간별 검출률. 특히 베이스 이동 중, 먼 거리, 집는 순간입니다.
- AV1 라벨과 JPEG 실행의 차이.
- 베이스를 포함한 시연의 품질과 학습 가능성.
- 필요한 시연 수. 초기안 100개는 경험에 근거한 추정이며 파일럿으로 점검합니다.
- 팔이 닿는 놓는 위치의 실제 후보.
